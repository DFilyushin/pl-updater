# План реализации: мониторинг поисковых запросов на pornolab.net

## 1. Цель

Десктоп-приложение (Windows, один exe) с графическим интерфейсом:

- в **настройках** пользователь ведёт список поисковых запросов для мониторинга;
- в **главном окне** — кнопка «Проверить» и таблица найденных веток;
- каждую позицию можно **подтвердить** («прочитано») — после этого она больше
  не появляется в списке вывода. Показываются только новые/непрочитанные темы.

## 2. Результаты разведки сайта (24.08.2026)

- Сайт доступен, движок семейства TorrentPier/phpBB (как RuTracker).
- **Поиск требует авторизации**: `tracker.php` без сессии редиректит на главную с формой входа.
- Форма входа: `POST https://pornolab.net/forum/login.php`, поля:
  `login_username`, `login_password`, `redirect` (hidden), `login` (submit).
  Сессия держится на cookies (`bb_*`), нужен cookie jar.
- **Капча: на форме входа сейчас отсутствует** (в HTML нет `captcha`/`cap_sid`/`cap_code`).
  Однако движок TorrentPier умеет показывать графическую капчу (поля `cap_sid` + `cap_code`)
  после нескольких неудачных попыток входа или при подозрительной активности.
  **Обход капчи не делаем**: при обнаружении — показываем картинку пользователю
  в диалоге и ждём ручной ввод кода.
- Кодировка сайта — **windows-1251** (учитывать при отправке запроса и парсинге).
- Поиск по торрентам: `tracker.php?nm=<запрос>`. Результат — таблица с id топика,
  названием, разделом (форумом), размером, сидами/личами, датой добавления.

## 3. Технологический стек

- **Python 3.12+**
- **GUI: Tkinter + ttk** (stdlib) — главное окно, таблица `ttk.Treeview`, диалоги
  настроек и капчи. Без внешних GUI-зависимостей — проще и надёжнее собирается
  PyInstaller'ом. (`Pillow` — только для показа картинки капчи в диалоге.)
- `requests` — HTTP-клиент с cookie jar (persist в файл).
- `beautifulsoup4` + `lxml` — парсинг HTML.
- `SQLite` (stdlib `sqlite3`) — запросы, найденные темы, статус «прочитано».
- **PyInstaller** — упаковка в единый `get-update-pl.exe` (см. п. 4.7).

## 4. Архитектура (модули)

```
get-update-pl/
├─ app/
│  ├─ config.py        # настройки: креды, интервалы, пути (settings.json рядом с exe)
│  ├─ session.py       # авторизация, cookie persistence, детект капчи
│  ├─ search.py        # запрос к tracker.php, парсинг результатов
│  ├─ storage.py       # SQLite: queries, topics (+ флаг read)
│  ├─ gui/
│  │  ├─ main_window.py    # кнопка «Проверить», таблица, отметка «прочитано»
│  │  ├─ settings_dialog.py# список запросов + креды + параметры
│  │  └─ captcha_dialog.py # показ картинки капчи, поле ввода кода
│  └─ worker.py        # фоновый поток проверки (чтобы GUI не подвисал)
└─ main.py
```

### 4.1 Главное окно (main_window.py)

- Кнопка **«Проверить»** — запускает проверку всех активных запросов
  в фоновом потоке (`worker.py` + `queue` → обновление GUI через `after()`),
  кнопка на время проверки блокируется, внизу — статус-бар прогресса
  («Вход… / Запрос 2 из 5… / Готово, новых: 7»).
- **Таблица результатов** (`ttk.Treeview`): колонки — Запрос, Название темы,
  Раздел, Размер, Сиды, Дата добавления. В таблице только **непрочитанные** темы
  (накапливаются между запусками, т.к. хранятся в SQLite).
- Действия над позицией:
  - **Клик/двойной клик по теме** — открыть ветку в браузере (`webbrowser.open`
    на `viewtopic.php?t=<topic_id>`).
  - **Кнопка «Скачать торрент»** (рядом с «Подтвердить», плюс пункт контекстного
    меню): скачивает `.torrent` выбранной темы через авторизованную сессию
    приложения (`dl.php?t=<topic_id>` — требует логина, браузер тут не подходит).
    Файл сохраняется в папку загрузок из настроек (по умолчанию — «Загрузки»
    Windows); имя файла — из заголовка `Content-Disposition` или id темы.
    Поддержать множественное выделение (скачать несколько). После скачивания —
    статус в статус-баре и опционально авто-отметка «прочитано» (флаг в настройках).
  - **«Подтвердить» (прочитано)** — кнопкой, по контекстному меню и по клавише
    Delete/Enter; поддержать множественное выделение. Тема помечается `read=1`
    и исчезает из таблицы навсегда.
- Меню: Файл → Настройки, Выход; Справка → О программе.

### 4.2 Настройки (settings_dialog.py)

- **Список запросов**: добавить / изменить / удалить / вкл-выкл (чекбокс активности).
- Креды pornolab (логин/пароль; пароль хранится в `settings.json` рядом с exe —
  предупредить пользователя, что файл содержит пароль).
- Параметры: пауза между запросами (по умолчанию 3–5 с), число страниц пагинации,
  **папка для сохранения .torrent-файлов**, авто-отметка «прочитано» после
  скачивания (вкл/выкл), прокси (опционально).
- Хранение: запросы — в SQLite; остальное — `settings.json` рядом с exe.

### 4.3 session.py — авторизация

1. Загрузить cookies из файла; проверить живость сессии (запрос `tracker.php`,
   признак: есть форма логина → сессия мертва).
2. Если мертва — `POST login.php` (`login_username`, `login_password`, `login=Вход`),
   кодировка cp1251.
3. **Детект капчи**: в ответе искать `input[name=cap_code]`, `cap_sid`, `<img>` капчи.
   Если найдена — скачать картинку и показать **captcha_dialog** (картинка + поле
   ввода); повторить POST с `cap_sid` + `cap_code`. Автораспознавания нет.
4. Ограничить попытки входа (2–3), чтобы не провоцировать капчу/бан.

### 4.4 search.py

- `search(query) -> list[Topic]`: `Topic = {topic_id, title, forum, size, seeders, leechers, added_at, url}`.
- Запрос `tracker.php` c `nm=<query>` (перекодировка запроса в cp1251).
- Пагинация (`start=`) — первые N страниц из настроек; сортировка по дате
  добавления (новые сверху), тогда хватает 1–2 страниц.
- `download_torrent(topic_id, dest_dir) -> Path`: GET `dl.php?t=<topic_id>` через
  ту же авторизованную сессию; проверка, что ответ — torrent (Content-Type /
  сигнатура `d8:announce`), а не страница логина → иначе релогин и повтор.

### 4.5 storage.py (SQLite)

```sql
queries(id, text, enabled, created_at)
topics(topic_id PRIMARY KEY, query_id, title, forum, size, seeders,
       added_at, first_seen_at, read INTEGER DEFAULT 0)
```

- Новая тема = `topic_id`, которого ещё нет в `topics`.
- «Подтвердить» → `read=1`; в таблицу главного окна попадают только `read=0`.
- `topic_id` уже виденной темы повторно не добавляется — прочитанное не возвращается.
- Первый запуск нового запроса: всё найденное сохраняется как непрочитанное
  (пользователь сам массово подтвердит неинтересное; опция «первый прогон без
  вывода» — в настройках).

### 4.6 worker.py

- Проверка идёт в отдельном потоке: сеть не блокирует GUI.
- Пауза 3–5 с между запросами; ошибки сети/парсинга — в статус-бар и лог,
  проверка остальных запросов продолжается.
- Запрос капчи из потока — через событие в GUI-поток (диалог), поток ждёт ответ.

### 4.7 Сборка в исполняемый файл

- **PyInstaller `--onefile --windowed`** → `get-update-pl.exe` (GUI-приложение,
  без консольного окна: капча и статус — в самом интерфейсе).
- Данные рядом с exe (`Path(sys.executable).parent` при `sys.frozen`):
  `settings.json`, `data.sqlite3`, `cookies.dat`, `app.log`, `debug/`.
  Первый запуск — открыть окно настроек, если креды не заполнены.
- Скрипт сборки `build.ps1`: `pyinstaller --onefile --windowed --name get-update-pl main.py`.
- Нюансы: возможные ложные срабатывания антивирусов на onefile (запасной вариант
  `--onedir`); размер ~15–25 МБ — норма.

## 5. Вежливость к сайту / надёжность

- Пауза 3–5 с между запросами, один запрос за раз, User-Agent обычного браузера.
- Retry с backoff на 5xx/сетевые ошибки; на 403/капчу — остановка и диалог пользователю.
- HTML при ошибке парсинга сохранять в `debug/` (вёрстка может меняться).

## 6. Безопасность

- Креды в `settings.json` рядом с exe; файл и база — в `.gitignore`, в репозиторий
  не попадают. В диалоге настроек — предупреждение о хранении пароля.
- Рекомендация: сменить пароль, если он передавался по открытым каналам.

## 7. Этапы работ

| # | Этап | Результат |
|---|------|-----------|
| 1 | Каркас: config, storage, скелет GUI (окно + пустая таблица) | запускается окно |
| 2 | Авторизация + cookies + диалог капчи | стабильная сессия |
| 3 | Поиск и парсинг `tracker.php` | список веток по запросу |
| 4 | Диалог настроек со списком запросов | управление запросами |
| 5 | Кнопка «Проверить» + worker + заполнение таблицы + «Подтвердить» | рабочий MVP |
| 5а | Открытие темы в браузере + кнопка «Скачать торрент» | работа с темами |
| 6 | Полировка: пагинация, прокси, массовое подтверждение, логи | финальная версия |
| 7 | Сборка PyInstaller (`build.ps1`), проверка exe на чистой машине | `get-update-pl.exe` |

## 8. Риски

- Смена вёрстки/защиты сайта → парсер сломается (митигация: debug-дампы, тесты на сохранённых HTML).
- Капча на входе → ручной ввод через диалог (заложено).
- Блокировки сайта у провайдера → поддержка прокси в настройках.
- Истечение сессии → авто-релогин (заложено в session.py).
